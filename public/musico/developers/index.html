One Extension Model, Three Native Workflows

Every Musico extension exports a manifest plus async/sync CommonJS hooks on module.exports. Depending on the capabilities you declare, your plugin plugs directly into one or more native workflows:

  1. Custom Cloud Sources ("playlist", "tree", "stream"): Joins the same CloudSourceProvider pipeline as YouTube, Bilibili, and Google Drive, automatically getting Save to Local Folder, Update from Cloud, Playlists, and custom badgeLabel pills.
  2. Extension-Only Cloud Search ("search"): Unlocks the opt-in Search Source Switcher in Songs (hidden when no search extensions are enabled), ephemeral playback excluded from Library & Stats, and playlist/album preview sheets.
  3. Custom Cloud Lyrics ("lyrics"): Appears inside Lyrics → Search Online… alongside LRCLIB and NetEase, never running automatically during playback.

Packaging Formats & Auto-Update

Format Structure Best For
Single-File (.musico.js) One JS file exporting { manifest, ...hooks } on module.exports. Quick scripts, simple sources, easy sharing.
Bundle Archive (.musicoext) Standard .zip with manifest.json, index.js (or manifest.entry), and optional icon.png. Extensions with icons, assets, or multi-file packaging.
Multi-Plugin Pack (.zip) ZIP containing multiple *.musicoext bundles (such as musico-plugins-all.zip). One-URL community plugin suites with per-plugin updateUrl.

Inside Musico, packages extract to <AppData>/Extensions/<id>/ (or .\Data\Extensions\<id>\ in Windows Portable mode). ZIP importers enforce path traversal rejection (no ../ or absolute paths), max 256 entries, and max 16 MB uncompressed size.

8 Hook Contracts & Cross-Platform Schemas

  • canHandle(input) (sync, required for "playlist" / "tree"): input { rawText, extractedUrl } → returns { matched, normalizedUrl?, remoteId?, kind?: "playlist" | "folder" | "track" }.
  • fetchCollection(ctx, req) (async, required for "playlist" / "tree" & search previews): input { url, cookie?, cursor? } → returns { remoteId, title, tracks: ExtTrack[], subfolders?: ExtSubfolder[], nextCursor? }.
  • fetchFolder(ctx, req) (async, required for "tree"): input { folderId, pathSegments, depth, cookie?, cursor?, extra? } → returns { folderId, tracks: ExtTrack[], subfolders?: ExtSubfolder[], nextCursor? }.
  • resolveStream(ctx, req) (async, required for "stream"): input { remoteTrackId, relativePath?, cookie?, forceRefresh, quality?, purpose?: "stream" | "download" } → returns { url, headers?, fileExtension, mimeType?, expiresAtMs?, fallbackUrls?, contentLength?, actualQuality?, qualityLabel?, bitrateKbps? }.
  • search(ctx, req) (async, required for "search"): input { query, kind: "all" | "track" | "playlist" | "album", limit, cursor?, cookie? } → returns { items: ExtSearchResult[], nextCursor?: string | null } (or null).
  • searchLyrics(ctx, req) (async, required for "lyrics"): input { title, artist, album?, durationSec? } → returns ExtLyricsCandidate[] | { candidates: [...] } | { results: [...] } | null.
  • startQrLogin(ctx, req) (async, required for "qr_login"): input {} → returns { sessionId, qrContent, expiresAtMs?, pollIntervalMs?, message? } (qrContent ≤ 512 UTF-8 bytes; pollIntervalMs clamped to 1000–10000 ms).
  • pollQrLogin(ctx, req) (async, required for "qr_login"): input { sessionId } → returns { status: "pending" | "scanned" | "confirmed" | "expired" | "error", cookie?, accountName?, message? }.
Cross-Platform Gotcha: Always emit string remoteTrackId!

In ExtSearchResult (when kind === "track"), Apple strictly requires string remoteTrackId, whereas Android/Windows also fall back to id. Emitting remoteTrackId: String(item.id) keeps your extension 100% portable across all three clients.

Host Bridge (ctx), Cookies & Runtime Guardrails

  • await ctx.http.request({ method?, url, headers?, body?, followRedirects?, timeoutMs?, returnBytes? }): Routes through native HTTP stacks (honoring Windows HTTP Proxy when "proxy" is declared). Enforces permissions.hosts on the initial URL and every redirect hop (up to 10 hops), strips Cookie and Authorization across host changes, caps responses at 8 MB, and exposes lowercase headers plus raw setCookies array and optional bytesBase64.
  • ctx.crypto: md5, sha1, sha256, hmacSha256(key, msg) (lowercase hex), plus base64Encode / base64Decode.
  • ctx.kv: Persistent per-extension store: get(key), set(key, val, ttlSeconds?), remove(key). Because every hook runs in a fresh isolated JS VM, global variables never persist across calls; always store short-lived tokens in ctx.kv.
  • ctx.settings.get(key) & ctx.env: Read user settings and inspect { platform: "ios" | "macos" | "android" | "windows", appVersion, apiVersion: 1 }.
  • ctx.log (info / warn / error): Writes to the 200-entry ring buffer in Extension Manager. Never pass req.cookie into ctx.log (Android and Windows also auto-redact raw/URL-encoded cookies as defense-in-depth).
  • Limits & Portable JS Subset: 15s timeout on canHandle, resolveStream, search, and searchLyrics; 60s on fetchCollection/fetchFolder; 32 MB heap limit on QuickJS & Jint. Use ES2020 + CommonJS module.exports + ctx.* only (no Node require/fs/Buffer, no window/document).

Standard Error Codes

Attach err.code to thrown errors so Musico displays localized guidance and triggers auth/retry UX appropriately:

CodeWhen to Throw
INVALID_URLInput URL does not match a valid collection or resource ID.
AUTH_REQUIREDMissing, private, or expired session req.cookie.
EMPTY_COLLECTIONCollection loaded cleanly but contains zero tracks or subfolders.
NO_PLAYABLE_STREAMTrack has no playable stream or upstream rejected stream lookup.
RATE_LIMITEDUpstream returned HTTP 429 or rate-limit payload.
NETWORK_ERRORUpstream HTTP 4xx/5xx, invalid JSON, or connectivity failure.
PERMISSION_DENIEDHost or URL scheme blocked by permissions.hosts.

Detailed UX & Engineering Guidance

1. Minimal Host Permissions

Declare only the exact domains your API and CDN use inside permissions.hosts. Every user sees this list during Permission Review before enabling your extension.

2. Clear Auth & Cookie UX

Fail loudly with AUTH_REQUIRED and a plain-language message (or implement qr_login). Never require cookies for public endpoints, and never log secrets.

3. Pagination & Preview Respect

Respect req.limit and req.cursor, return nextCursor: null when done (never echo the same cursor), and include sourceUrl on search playlists/albums so users can preview before adding.

4. Quality, Purpose & Memory Safety

Honor req.quality and req.purpose ("stream" vs "download"), set accurate fileExtension/mimeType, use https:// artwork URLs, and keep JSON payloads small for QuickJS/Jint's 32 MB heap.
