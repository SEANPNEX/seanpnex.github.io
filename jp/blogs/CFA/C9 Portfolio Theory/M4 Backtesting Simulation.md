# バックテストとシミュレーション

**バックテスト**は、過去のデータを使ってモデルや投資戦略を検証する。その戦略を過去に実行していたらどうなっていたかをシミュレートする。

- 投資戦略のバックテストの手順：
  1. **戦略の設計**
     - 投資仮説と目標を明確にする。
     - 投資ルール、プロセス、主要なパラメーターを決める。
  2. **過去の投資のシミュレーション**
     - 投資ルールに従って、各期間にポートフォリオを構築し、リバランスする。
     - 通常は**ローリング・ウィンドウ**で行う。各リバランス日に、その日までに入手できたデータだけでポートフォリオを作り、次の期間（アウト・オブ・サンプル）保有し、前に進めて繰り返す。
  3. **バックテスト結果の分析**
     - ポートフォリオのパフォーマンス統計を計算する。

確認すること：

* **平均リターン**と、シャープ・レシオなどのリスク調整後の指標。
* **ボラティリティ**：リターンの標準偏差。
* **下方リスク**：リターンは正規分布でないことが多い（負の歪度、ファット・テール）ので、ボラティリティだけでは足りない。
  * [VaR](M3%20Managing%20Market%20Risk.md#value-at-risk-var) と [CVaR](M3%20Managing%20Market%20Risk.md#extensions-of-var)：テールの損失。
  * **最大ドローダウン**：ポートフォリオの価値のピークからその後の谷までの最大の下落。例えば、120 まで上がってから 90 まで下がり、その後回復したポートフォリオのドローダウンは $90/120-1=-25\%$。

よくある 3 つの問題が、バックテストを実際の戦略よりよく見せることがある。

* **生存者バイアス**：データに今日も存在する会社しか含まれず、破綻した、上場廃止になった、買収された会社が抜けている。負けた会社が除かれるので、リターンは**過大**に、リスクは過小に評価される。対策：消滅した会社も含めてすべての会社を残すデータベースを使う。
* **先読みバイアス**：判断の時点では**入手できなかった**情報を使う。例えば、期末の数か月後に発表された年間利益や、後で修正されたデータ。対策：**ポイント・イン・タイム**のデータを使い、報告の遅れの分だけデータをずらす。
* **データ・スヌーピング**：同じデータで多くの戦略やパラメーターを試し、偶然うまくいったものだけを報告する。対策：戦略の設計に使っていないデータで検証し（**アウト・オブ・サンプル**の検証、交差検証）、有意性のハードルを上げる（例：$t$ 値 3 超）。

## シミュレーション

バックテストが示すのは、歴史がたまたまたどった**1 本の経路**だけである。シミュレーションは多くのありうるシナリオを作り、歴史より悪いシナリオも含めて、戦略がそれぞれでどうなるかを見る。

* **ヒストリカル・シミュレーション**：過去のデータから無作為に選ぶ。例えば、過去の月次リターンを復元抽出して多くの新しい経路を作る（**サンプリング**、**ブートストラップ**）。
  * ファット・テールや資産間の相関を含め、リターンの実際の分布を保つ。
  * 一度も起きたことのない結果は生み出せず、過去が代表的だと仮定している。
* **モンテカルロ・シミュレーション**：統計的な分布、通常は資産の平均、ボラティリティ、相関をもつ**多変量分布**を設定し、そこから無作為にシナリオを引く。
  * 柔軟：歴史を超えるシナリオや、ファット・テールや歪みのある分布をモデル化できる。
  * 結果は想定した分布とそのパラメーターに依存する（モデル・リスク）。

**感応度分析**は、異なる前提でシミュレーションをやり直す。例えば正規分布の代わりにファット・テールの分布を使い、戦略の結果が崩れないかを確かめる。
